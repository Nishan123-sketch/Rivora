# Local GPU assistant upgrade

Rivora Assist now uses the official Qwen3-4B Q4_K_M model through a private CUDA-enabled llama.cpp runtime on this computer. The previous 1B model is retained as a fallback file. The 4B weights are approximately 2.5 GB and are checksum-verified against the publisher's metadata. Model source and Apache 2.0 license: https://huggingface.co/Qwen/Qwen3-4B-GGUF. Runtime source: https://github.com/ggml-org/llama.cpp/releases/tag/b12182.

Verified local configuration: RTX 3050 Ti Laptop GPU with 4096 MiB VRAM, 4096-token context, one inference slot, full GPU offload, thinking disabled for normal chat. Measured GPU allocation was 3133 MiB. Do not increase the context without checking memory again.

Windows initially retained startup model pages in system RAM, causing severe memory pressure and a MySQL thread creation failure. The local launcher now releases only its own model child's startup working-set pages after GPU loading. This preserves GPU weights and avoids keeping the startup copy resident. It does not trim other applications. Subsequent live verification showed approximately 2.2 GB of system RAM available while the database and model were running. These are snapshots of this computer, not minimum hosting specifications or capacity guarantees.

## Functional improvements

Follow-up questions retain their subject and resolve a new location when supplied. A river-level question followed by “tomorrow” cannot silently become a weather forecast. Predictions are bounded to the requested date. Wind forecasts show wind, rainfall questions show rainfall and precipitation chance, and main answers omit unrelated measurements. Explicit names and project names can be recalled from recent user messages without reading account records. Missing context is acknowledged. Historical warning questions read stored bulletins and acknowledge incomplete coverage. Concept explanations focus on the requested metric. Invalid negative rainfall/wind and impossible percentages are withheld; genuine zero readings remain valid.

## Measured checks

The same three model-only checks were run before and after the upgrade. The old CPU model needed about 13.7 seconds for presentation help, failed the project-name recall check, and exceeded 20 seconds on general demo tips. The fully GPU-offloaded 4B model passed all three checks at approximately 4.6, 0.7 and 3.1 seconds. These small deterministic acceptance checks do not establish universal model quality.

The running application then returned ordinary conversation in 821 ms, explicit conversation recall in 12 ms, a river follow-up in 292 ms, a stored wind forecast in 24 ms and historical-warning retrieval in 123 ms. Response times vary with workload, output length and cache state. The factual retrieval path remains separate from model generation. Verification JSON and test logs are included in docs/verification.

## Startup and recovery

Existing backend/.env selects the private runtime at http://127.0.0.1:11435. Relevant settings are LLM_PROVIDER=llamacpp, LLM_MODEL=qwen3:4b, LLM_LOCAL_EXECUTABLE, LLM_LOCAL_MODEL_PATH, LLM_GPU_LAYERS=99 and LLM_LOCAL_CONTEXT=4096. Absolute local executable/model paths are machine-specific. Secrets and actual .env are not distributed in the source ZIP.

Starting the backend checks the configured private listener and starts the local runtime when absent. It does not rely on an old PID to suppress recovery. On Windows, scripts/run-local-model.py performs the startup memory adjustment for the GPU model. Ordinary conversations are buffered and checked before delivery; reasoning markup is not exposed as the answer. Missing observations are still not generated by the model.

The source ZIP excludes large model weights, executable binaries, node_modules and .env. On another Windows/NVIDIA development machine, backend/scripts/setup-local-model.py downloads and verifies the pinned model/runtime assets using Python's standard library. It can reuse verified installed files. Review the hardware configuration and benchmark before activation. The model license is saved beside the local weights. Keep the runtime bound to loopback.

## Hosting later

The Windows executable is for local development. A Linux deployment needs a suitable Linux inference runtime and model paths, or a configured cloud provider. The backend's existing Gemini/OpenAI/Anthropic adapters remain available; no paid provider was enabled by this change. Inference must stay private behind the backend. The frontend must never receive provider keys. Test concurrent users and data-collection jobs on the actual hosting server before choosing its capacity.
