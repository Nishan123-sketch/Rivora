# Level forecasting audit before implementation

Live snapshot on 8 November 2026: API reports 789 monitored gauges, 759 ready level forecasts, zero experimental grades, zero validated warning models and 28 live official coverage gauges. The supplied zero-forecast state is not currently reproduced. Readiness checks report age (24h), input freshness and valid-at times; delayed hourly jobs can expire all horizons. This is independent of warning coverage/calibration. Existing jobs run hourly when enabled.

Existing level algorithm: station-specific standardized Ridge (fixed lambda 5), lag changes 1/3/6h, optional past-6h point rainfall, direct 1/3/6h targets, persistence baseline. Samples use up to 4,000 latest readings and 65/82% chronological split with 6+h purge. Selection is by validation MAE improvement; final metrics are retrospective. Selected models are refitted on all known samples inside request handling, cached 60s, with no versioned level artifact. All-data refit is not the same fitted model used for reported holdout scores. Final test availability also affects rainfall variant choice, and live inputs affect model selection. These must be separated.

Official data enters through WAMIS, HRFCO bulk/dated history and KMA jobs into water_readings and provider-specific rainfall tables. Advanced level routes call getOutlook, store ml_advanced_predictions and expose metrics through advanced-ml-service to MLAdvanced.jsx. A network refresh aggregates forecasts and writes advanced-level-network.json and per-station model reports. Warning artifacts are separate Python joblib files and stay unchanged.

Taehwa audit: 9,817 stored readings, July 2025–November 2026, with 9,670 missing source_url. A substantial 2025/2026 level shift requires a quality flag; it is not proof of a datum conversion or fake data. Raw rows will remain untouched. Official history will be reconciled in a separate derived table. Training will require known station-matched provenance; no unknown rows are silently promoted.

Acceptance policy was written to backend/ml/level_policy.json before fitting the new level candidates. It defines independent level splits, embargo, minima, baselines, candidate families, per-regime checks, block-bootstrap criteria and interval coverage gates. Warning partitions, purge, minimum events, archive coverage and calibration outcome are protected by file hashes.
